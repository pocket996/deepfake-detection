# 系统架构

## 1. 设计原则

- 回放优先：先用确定的公开数据打通链路；
- 模块解耦：算法、实时引擎和小车可以分别测试；
- 配置驱动：数据路径、滤波参数、窗口参数和串口参数不硬编码；
- 可追溯：每个预测和控制命令都有时间戳与日志；
- 失效安全：任何未识别状态都转换为 `STOP`；
- 不把回放实验描述为真人在线控制。

## 2. 模块

```text
dataset → preprocessing → model → replay → decision → transport → firmware
                                      ↓            ↓            ↓
                                    logging      watchdog     motors
```

### dataset

负责公开数据的获取说明、读取、通道与标签对齐。仓库不直接提交完整数据集。

### preprocessing

负责滤波、切窗和训练阶段所需的特征变换。所有需要拟合的参数只能在训练数据上拟合。

### model

负责训练、保存和加载 CSP+LDA pipeline，并输出预测类别和置信度或可比较的决策分数。

### replay

按照原始时间顺序产生数据块或窗口，模拟实时数据到达，不允许提前读取未来窗口影响当前预测。

### decision

负责置信度门控、连续窗口确认、动作冷却和默认停车。模型输出不能直接写入电机。

### transport

负责上位机与小车之间的消息编码、发送、确认、超时和重连。协议见 [PROTOCOL.md](PROTOCOL.md)。

### firmware

负责命令校验、电机动作、watchdog 和物理急停。下位机不得依赖上位机持续发送 `STOP` 才能保证停车。

### logging

记录实验配置、数据标识、模型版本、窗口时间、分类结果、控制命令、ACK 和关键延迟。日志不得包含密钥或可识别个人信息。

## 3. 建议目录

```text
configs/
docs/
firmware/
scripts/
src/eeg_wheelchair/
├── data/
├── preprocessing/
├── models/
├── replay/
├── control/
└── transport/
tests/
```

目录可在实现初始化 PR 中建立。本文件只固定职责边界，不提前锁定内部类、函数或第三方库。

## 4. 集成顺序

1. 用固定样例测试数据与预处理接口；
2. 用离线窗口测试模型接口；
3. 用虚拟时钟测试回放与决策接口；
4. 用模拟串口测试通信和超时；
5. 用手动命令测试真实小车；
6. 最后连接回放、分类、通信和小车。

每次集成只替换一个模拟模块，以便定位故障。
