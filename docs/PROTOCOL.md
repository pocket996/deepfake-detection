# 小车通信协议草案

状态：`draft-v0.1`。本协议用于固定上位机与下位机的最小边界；字段编码可在硬件实现前通过 Pull Request 调整。

## 1. 安全要求

- 下位机上电后默认为停止；
- 未识别、缺字段、校验失败或过期的消息不得触发运动；
- 每个运动命令必须包含有限持续时间；
- 命令执行完毕后自动停止；
- 超过 watchdog 时限未收到有效消息时自动停止；
- `STOP` 的优先级高于其他命令；
- 物理急停直接禁止电机输出，不依赖软件状态。

## 2. 逻辑命令

| 命令 | 含义 | 必要参数 |
|---|---|---|
| `LEFT` | 低速短时左转 | 序号、持续时间 |
| `RIGHT` | 低速短时右转 | 序号、持续时间 |
| `STOP` | 立即停止 | 序号 |
| `PING` | 保持连接并检查下位机 | 序号 |

MVP 不定义前进、后退或连续转向命令。

## 3. 响应

下位机至少返回：

- `ACK`：命令已通过校验并接受；
- `DONE`：有限时长动作已完成并停车；
- `ERROR`：命令无效或无法执行；
- `STATE`：当前为停止、执行中或急停状态。

最终编码需补充消息分隔符、字段顺序、单位、最大持续时间、重复序号处理、watchdog 时限和错误码。

## 4. 变更规则

实现代码必须引用协议版本。任何不向后兼容的变更都需要同时修改上位机、下位机、模拟器和协议测试，并通过同一个或相互关联的 Pull Request 提交。
